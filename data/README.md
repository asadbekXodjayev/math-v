# data/ — MathGen data v1

Generated by `scripts/build_data.py`. The design is pre-registered in [`research/RESEARCH_DESIGN.md`](../research/RESEARCH_DESIGN.md) §3; see [`dataset_card.md`](dataset_card.md) for what the data contains and its known limitations.

The JSONL files are **regenerable and gitignored**. Only `manifests/build.json` is committed: it pins the sha256 of every file, the config hash and the hash of the generating code.

## Build

```
.venv/Scripts/python.exe scripts/build_data.py --config configs/base.yaml
```

- About 45 s on the project laptop.
- Every item is checked against the independent oracle (`src/mathgen/eval/oracle.py`) while it's written; any disagreement aborts the build.
- Running the build twice gives a byte-identical manifest. That is tested in `tests/test_data.py::test_build_is_deterministic`, and was verified on the full build.
- `pytest -q tests/test_data.py::test_built_data_matches_committed_manifest` checks local files against the committed manifest.

## Layout

| Path | Items | Content |
|---|---|---|
| `eval/test_id_unseen.jsonl` | 2,672 | G-set instances from the test pool (hash bucket ≥ 750): the **primary endpoint** |
| `eval/val.jsonl` | 644 | G-set val pool (700 ≤ bucket < 750); LR and budget selection only |
| `eval/block.jsonl` | 1,069 | the 7 pre-registered block regions B1–B7, held out of all training |
| `eval/ood_same.jsonl` | 1,248 | operands outside the ID range, same digit count |
| `eval/ood_longer.jsonl` | 2,189 | operands with one more digit than the ID maximum |
| `fit/tokenizer_fit.jsonl` | 50,000 | fixed train-pool sample (stream "fit", seed 0) used to fit every tokenizer |
| `train/seed{0..4}.jsonl` | 128,000 each | training stream for run seed *s*; **the first N lines are the size-N training set** (N ∈ {2K, 8K, 32K, 128K}, nested) |
| `manifests/build.json` | — | sha256 per file and per training subset, space sizes, G/M sets, oracle agreement, context-length measurement |

The **train-recall** split (seen instances, for H3) is not built here. It depends on each run's training set, so it is drawn per run at evaluation time.

## Record fields

- **Training lines:** `template, key, operands, question, hints, answer, atype`.
- **Eval lines** add:
  - `split, family, set (G/M), bucket, block_id, ood_kind`;
  - `n_hints`, `n_comp_steps` (hints containing "= <number>");
  - `magnitude` (largest |operand|);
  - `tchar_len` (prompt + hints-first target, in character-tokenizer tokens).
